# 异常术语与描述判据草案

记录日期：2026-10-23

状态：内容草案，已据此重写 [annotation-rules.md](../resources/annotation-rules.md)。多轮输出协议已确定，应用侧仍待接入，见[注解多轮反馈与输出协议](注解多轮反馈与输出协议.md)。

## 1 目标与适用范围

注解用于表明图片中各码区的问题、异常位置和具体表现。本文承接[注解分析角度](注解分析角度.md)，把十个观察角度细化为术语含义、使用依据、描述要点、易混淆边界及示例，为重新生成 [annotation-rules.md](../resources/annotation-rules.md) 提供内容基础。

当前入口是人工描述规范化：模型处理当前图片记录的人工原始描述及后续选择、补充和修正，不读取图片，不补造材质、码型、位置、异常、原因、程度或解码结果。本文中的“表现”和“判据”帮助理解文字含义、选择恰当用词，也可供人工组织观察；它们不是要求模型自行执行的视觉检查任务。

每一次接收信息并分析后，都必须重新识别歧义及可细化信息。该步骤贯穿首轮输入和所有后续反馈；存在需要确认的内容时提供相关选项，接收反馈后再次分析和检查，满足结束条件后再生成最终注解。

术语集合保持开放。人工描述有明确含义但未出现在本文中时，应保留并规范表达，不为了匹配分类删掉信息。十个角度也不是必须填满的字段，同一问题可以涉及多个角度。

## 2 使用术语前的共同判断

### 2.1 根据原文的信息层次选择表达

| 原文提供的信息           | 规范化处理                                     | 示例                                            |
| ------------------------ | ---------------------------------------------- | ----------------------------------------------- |
| 明确的异常名称           | 保留名称，必要时统一同义词；不要求人工额外证明 | “左码反光”→“左侧码区存在反光。”                 |
| 可明确等义转述的表现     | 转为含义相同的术语，保留关键细节               | “右码的黑白颜色很接近”→“右侧码区黑白对比度低。” |
| 可由多种异常产生的表现   | 保留表现，不替用户选定原因或细分类别           | “中间白了一块”→“中部局部发白。”                 |
| 带不确定性的判断         | 保留不确定性及其作用对象                       | “可能是反光”→“疑似存在反光。”                   |
| 仅有笼统问题描述         | 保持原有信息粒度，不扩展成具体缺陷清单         | “印刷质量差”→“存在印刷质量问题。”               |
| 明确正常、否定或解码结果 | 保留其范围及条件，不能扩展为全面正常           | “能解码，但有反光”→“存在反光，但可以解码。”     |

“使用依据”不意味着每次输入都必须包含详细证据。人工已明确说“失焦”“透视变形”时可以保留；只有模型准备从较宽泛的描述转成更具体术语时，才需要检查原文是否足以支持该转换。

对于无法等义规范的词，先保留可理解的原话，再按 2.4 节反馈澄清。“糊”可能表示模糊，也可能表示印刷糊连；“缺了一块”可能表示缺损、遮挡或未拍全，均需结合上下文，不能固定替换。上述表格说明已有信息如何表达，不表示可以跳过反馈直接完成注解。

### 2.2 分清描述对象

| 对象             | 本文用法                                           | 不能混淆的边界                                                         |
| ---------------- | -------------------------------------------------- | ---------------------------------------------------------------------- |
| 图片或整图       | 全图层面的亮度、清晰度、背景等信息                 | 全图问题不能擅自改为某一个码的问题；全图偏暗不自动推出每个码低对比度   |
| 码区             | 一个条码在图片中的整体区域                         | 多码时需沿用人工提供的编号、相对位置或其他标识                         |
| 码元             | 泛指条码中构成码纹的单元；用于原文未区分具体类型时 | 不因“码元”一词自行判断码型                                             |
| 条与空           | 一维条码中编码所用的条及间隔                       | 条和空本来可以有不同宽度，不能仅凭宽窄不一判定缺陷                     |
| 模块             | 二维矩阵码中的单元，可为明或暗                     | 不能把正常相邻同色模块组成的连续区域直接判定为粘连                     |
| 点阵中的点       | 人工描述的点状成码元素                             | 点之间有间隔可以是正常成码方式；点形状和尺寸也不能脱离原文强制判断异常 |
| 定位等结构性图案 | 原文明确识别出的定位、校正、定时或边缘结构         | 不根据“角落的方块”等泛称自行确认码型和结构名称                         |
| 静区             | 码外围按码型要求保留的空白区域                     | 不是所有码内白色间隙都叫静区；裁剪图边缘不等于原始静区边缘             |

原文写黑、白时保留黑白信息；原文为浅色码、深色底时保留其极性。未给出颜色时优先使用“条空”“模块”“间隙”等表达，不强行套成黑码白底。

### 2.3 每项问题按已有信息组织

推荐表达顺序为：目标标识＋目标内位置或作用范围＋现象＋已有程度＋具体表现或影响。顺序以自然可读为准；缺失信息先检查是否需要澄清或值得细化，最终仍无依据的部分省略或保留相应不确定性，不输出占位词。

例如“右边码的下面几个块粘在一起，白缝没有了”可规范为：“右侧码区底部部分模块粘连，局部白色间隙消失。”这里的“粘连”和“间隙消失”描述同一问题的名称与表现，不应再额外生成“印刷不良”“墨水扩散”等推断。

### 2.4 每轮分析后的识别与反馈

#### 固定循环

每轮按以下顺序处理，不仅在首次输入时执行：

1. **接收并分析信息。** 接收原始描述、选项选择、自由补充、修正，或“无法判断”“保持原描述”等反馈，理解本轮信息的目标、范围和含义。
2. **合并当前记录的有效信息。** 保留已确认事实、否定、程度和不确定性；明确修正只替换其对应内容。未被本轮提及的已有事实不能丢失，模型提出的候选项不能作为事实合入。
3. **重新识别歧义及可细化信息。** 检查本轮新增内容、与已有信息的关系，以及当前记录尚待处理的问题。不能因为用户刚回答了一个问题，就跳过此步骤直接生成注解。
4. **决定是否继续反馈。** 有待消除的歧义或有价值的细化点时，提出针对性的选项或补充问题；没有需要继续反馈的内容时，进入最终规范化。
5. **接收下一轮反馈后回到第 1 步。** 用户仅作选择或表示无法判断，也属于新一轮信息，仍需分析并检查其余内容和结束条件。

每轮都检查，不代表每轮都必须提问。检查的目的在于发现影响含义或能提高异常描述价值的信息，不是把十个分析角度逐项填满。

#### 区分消除歧义与补充细节

| 类型     | 触发情况                                                 | 反馈目标                               | 例子                                               |
| -------- | -------------------------------------------------------- | -------------------------------------- | -------------------------------------------------- |
| 消除歧义 | 目标、位置、词义、程度作用范围不清，或信息互相冲突       | 确认原话具体指什么，避免归属或术语错误 | “右边模糊”是右侧的码模糊，还是某个码的右侧部分模糊 |
| 补充细节 | 已有描述有效，但存在与该异常直接相关、值得确认的细分信息 | 让用户有机会提高描述的具体程度         | 已知“模糊”，进一步确认运动模糊、失焦模糊或其他情况 |

“模糊”可以是有效描述，但类型未说明时仍应提供细化机会，不能因为已经能生成一句注解就跳过。类型、范围、程度或受影响结构是否值得询问，应结合当前内容判断；不自动询问所有缺失字段，也不推测尚未提到的异常。

#### 选项组织

- 明确指出本次问题对应哪个码区、哪项现象，以及需要确认的具体含义。目标不明时先澄清目标，不能在问题中擅自指定。
- 选项围绕当前问题，使用用户容易理解的表述；必要时简短解释术语。提示表现不能被写成确定诊断或必然因果。
- 允许并存的情况应支持多选，或提供“两者都有”；明确单选与多选的含义，不设计相互冲突的强制选项。
- 提供“其他情况，可补充说明”“无法判断”和“保持原描述、不再细化”等路径。无法判断表示未知；保持原描述表示用户选择不继续细化，不能因此补写“无法判断”这一事实。
- 可将同一目标的少量相关问题一起反馈；优先处理目标归属、词义和冲突，再处理依赖它们的细分问题。选项用于确认描述含义，不依赖标签字典。
- 没有选择、未回复、默认选中或超时均不代表确认。已提出的问题等待用户明确反馈，不把候选项或等待状态写入最终事实。

**模糊类型的反馈示例：**

> 你描述了右侧码区模糊，是否能进一步确认模糊类型？
>
> - 运动模糊。
> - 失焦模糊。
> - 两者都有。
> - 其他情况，可补充说明。
> - 无法判断类型。
> - 保持“模糊”描述，不再细化类型。

选择“运动模糊”后只补入该类型，不同时认定相机抖动、方向或程度。用户只补充“有向右的拖尾”时，保留该表现，不能把它当作已经选中“运动模糊”。

#### 反馈合并与停止条件

已经确认的问题不重复询问。用户对某项表示无法判断或不再细化时，记录其作用范围；后续每轮仍检查该项与新信息是否一致，但没有新依据或明确修正时，不重复发送同一个问题。对“类型无法判断”的反馈不能扩大为“位置、程度都无法判断”，对一项选择不细化也不能视为放弃其他问题。

新信息引入新的歧义、冲突或有价值的细化点时，应继续反馈。例如用户确认右码是运动模糊，同时补充“下面还有一块白”，需要重新判断“下面”指哪个目标及“发白”的含义。明确的自我修正可以更新已有结论；仅出现冲突不能默认为后一句覆盖前一句。

当所有相关问题已明确，或用户已针对剩余问题表示无法判断、保持原描述或结束细化，并且当前有效信息足以形成忠实的注解时，结束反馈并生成最终结果。用户选择整体结束细化后，仍进行本轮检查，但对尚不明确的信息采用原有粒度、保留不确定性或明确冲突，不继续强求细节。若连可理解的有效描述都无法形成，才按无法完成处理。

需要反馈时返回 `status: "needs_feedback"` 及非空的 `questions`，不包含最终注解；满足结束条件后返回 `status: "final"`、`completed` 和 `annotation`。具体字段约束见[注解多轮反馈与输出协议](注解多轮反馈与输出协议.md)。不能把待反馈状态混同为无有效输入、处理失败或已完成无异常。

## 3 十个角度下的术语与描述判据

本节每组示例中的信息均以人工原文为依据，展示有依据的表达及禁止推断。它们不是完整交互记录，不表示可以跳过 2.4 节的每轮检查与反馈；推荐表达也不是要求每条注解达到相同细节量的模板。

### 3.1 尺寸与有效细节

这一角度区分码在整图中的相对大小、码区的实际像素尺寸，以及条空或模块的可分辨细节。三者不能相互替代。模块像素尺寸是解码相关因素，但具体读取表现取决于输入和解码条件，本文不设统一像素阈值。[Dynamsoft 小模块说明](https://www.dynamsoft.com/barcode-reader/docs/core/programming/features/read-barcodes-with-small-module-size.html)

| 术语或表达                   | 含义与使用依据                           | 描述重点与边界                                             |
| ---------------------------- | ---------------------------------------- | ---------------------------------------------------------- |
| 大图小码、码区占比小         | 原文明确说码区相对整图很小               | 是相对尺寸特征，不自动等于低分辨率；保留“但模块清楚”等补充 |
| 码区像素尺寸小               | 原文明确涉及像素大小，或给出码区像素尺寸 | 原有尺寸和单位可保留，不由原图尺寸代算码区大小             |
| 模块像素尺寸小、码元细节不足 | 原文明确说明码元像素少或细节不足         | “像素少”与“看不清”不自动互换；不能仅从模糊推定采样不足     |
| 缩放后细节丢失、像素化       | 原文明确说明缩放关系或可见像素块         | 缩放因果必须由原文提供；看见锯齿不自动证明经过缩放         |

**正例：**“整张图很大，码只占一点，但小格还清楚。”→“大图小码，模块仍清晰。”

**反例：**不能改为“码区分辨率不足，模块无法辨认”；这同时补造异常并丢失原文的正常情况。

### 3.2 清晰度与边缘可分辨性

| 术语或表达             | 含义与使用依据                           | 描述重点与边界                                               |
| ---------------------- | ---------------------------------------- | ------------------------------------------------------------ |
| 模糊、边缘不清晰       | 原文明示模糊，或明确说边缘发虚、不清楚   | 保留整体或局部范围；“看不清”但原因不明时可直接保留“难以辨认” |
| 失焦模糊               | 人工明确判断失焦、未对准焦点             | 不由整体模糊单独推定；不能反推出拍摄距离或镜头问题           |
| 拖影                   | 原文明示拖影，或描述边缘向某方向拖尾     | 保留拖尾方向和位置；拖影不自动等于相机抖动                   |
| 运动模糊               | 人工明确使用该词，或明确说明运动导致模糊 | 保留已有原因关系，不把所有定向模糊强制归为运动模糊           |
| 重影                   | 原文明示重影，或同一轮廓存在错位重复影像 | 不合并成普通模糊而丢掉重复轮廓特征；不推断具体成因           |
| 边界难分、条空难以区分 | 原文明确说相邻元素在视觉上分不开         | 描述可分辨状态，不自动诊断实际印刷粘连                       |

**正例：**“左边那个码往右拖了一道影，右边的只是边缘发虚。”→“左侧码区存在向右拖影；右侧码区边缘不清晰。”

**反例：**不能统一写为“两个码均因相机抖动而严重模糊”。原因、程度和两码表现均被改变。

### 3.3 明暗对比与局部可分辨性

| 术语或表达               | 含义与使用依据                                 | 描述重点与边界                                         |
| ------------------------ | ---------------------------------------------- | ------------------------------------------------------ |
| 低对比度                 | 原文说明码纹与底色明暗差小，或明确使用低对比度 | 区分整体和局部；图片暗不必然等于条空对比度低           |
| 局部对比度低、对比度不均 | 原文说明不同位置的明暗区分能力不同             | 保留具体方位和对比关系，不把局部问题扩展到全码         |
| 码纹偏淡、局部变淡       | 原文描述码纹颜色浅或局部淡化                   | 不默认印刷褪色、曝光问题；“褪色”仅在人工作此判断时保留 |
| 明暗难以区分             | 原文表明某处明暗元素难辨，但未确认机制         | 保留表现；不能自动转换成反光、过曝或污损               |

**正例：**“左码上半截黑条跟底色太接近，下半截对比正常。”→“左侧码区上半部条纹与底色对比度低，下半部对比度正常。”

**反例：**不能写成“左侧码区整体曝光不足”。

GS1 的质量说明区分整体符号对比与局部明暗变化。本文借用这一观察区分，不把人工的“局部发淡”直接改为经过测量的调制度等级。[GS1 条码质量说明](https://ref.gs1.org/guidelines/2d-in-retail/)

### 3.4 光照、反光与曝光表现

| 术语或表达         | 含义与使用依据                       | 描述重点与边界                                                       |
| ------------------ | ------------------------------------ | -------------------------------------------------------------------- |
| 反光               | 人工明确判断为反光                   | 保留条状、点状等形态及覆盖位置；没有写反光时，局部发白不够支持该归因 |
| 高光、亮斑、亮带   | 原文给出局部强亮区域或其形状         | 保留原有命名和形态，不自动推定反射机制或细节丢失                     |
| 过亮、局部发白     | 原文描述亮度表现                     | 可与“条纹看不见”等已有影响并列，不自动改成过曝                       |
| 过暗               | 原文描述亮度偏暗                     | 不自动补充噪声、低对比度或解码失败                                   |
| 过曝、欠曝         | 人工明确使用曝光判断                 | 不根据“亮”“暗”擅自升级为曝光原因判断                                 |
| 阴影               | 人工明确指出阴影                     | 保留阴影覆盖范围；阴影不是实体遮挡，不自动写成码区被遮住             |
| 光照不均、亮度不均 | 人工明确说光照不均，或只描述明暗不均 | 若仅描述明暗分布，优先写“亮度不均”，不推定照明设备或方向             |

**正例：**“中间一块发白，里面条纹看不见，可能是反光。”→“码区中部局部发白，该处条纹不可辨，疑似反光。”

**反例：**不能写成“强光造成严重过曝，导致解码失败”。

### 3.5 几何形态与变形

| 术语或表达           | 含义与使用依据                         | 描述重点与边界                                                   |
| -------------------- | -------------------------------------- | ---------------------------------------------------------------- |
| 旋转、倾斜放置       | 原文描述码在图像平面内的方向           | 属于姿态特征，不自动属于几何缺陷；“歪”含义不清时不选定旋转或透视 |
| 透视变形             | 人工明确判断透视，或明确给出其几何关系 | 只有“梯形”“一边窄”时可直接保留形状；不根据姿态推测拍摄角度数值   |
| 拉伸、压缩、比例失衡 | 原文明确说明形状被拉长、压扁等         | 保留方向及局部/整体；长方形码本身不等于被拉伸                    |
| 弯曲                 | 原文说明码纹或码区沿曲面弯曲           | 区分载体弯曲与码纹可见弯曲；不因载体是瓶子就补写畸变             |
| 折皱、折痕干扰       | 原文说明褶皱或折痕及其与码区的关系     | 透明膜有褶皱不自动等于码本体变形；保留是覆盖层还是标签自身       |
| 局部扭曲、排列不规则 | 原文明确描述局部几何形态或排列异常     | 保留具体表现，不升级为标准网格测量结论                           |

**正例：**“码上面窄下面宽，里面格子靠上挤得很紧。”→“码区上窄下宽，上部模块排列紧密。”

**反例：**不能补成“拍摄倾角过大，造成严重透视压缩”。原文没有给出原因和程度。

### 3.6 完整性与可见范围

| 术语或表达             | 含义与使用依据                         | 描述重点与边界                                           |
| ---------------------- | -------------------------------------- | -------------------------------------------------------- |
| 遮挡                   | 原文说明码纹被物体或其他内容挡住       | 保留遮挡物、位置、范围；未知遮挡物时只写遮挡，不猜测材质 |
| 未拍全、画面截断       | 原文说明部分码区在原图画面之外         | 保留截断方向；不等同于码本体损坏                         |
| 裁剪不全               | 原文明确说明提供的局部图裁掉码区或周边 | 保留是输入视野问题，不推定原图未拍全或原码静区不足       |
| 破损、撕裂、磨损、划伤 | 人工明确指出实体损伤及其类型           | 有具体类型时保留，避免全部压成“污损”；不由发白推定磨损   |
| 污渍、污损             | 人工明确指出污染或使用笼统的污损表述   | 能区分污染与破损时分开；只说污损时不补污染来源           |
| 局部缺失、局部不可见   | 原文只确认缺了一块或看不到部分码纹     | 原因未知时保留缺失或不可见状态，不选定遮挡、磨损或截断   |

**正例：**“右码最右边没拍进来，左码中间被贴纸挡住。”→“右侧码区右缘未拍全；左侧码区中部被贴纸遮挡。”

**反例：**不能概括为“两个码均有破损”。

### 3.7 条、空与模块的形态缺陷

这一组最容易把正常码纹误写成缺陷，或把成像问题误写成印刷问题。术语应表达人工已经指出的异常关系，不由“黑色连在一起”等单一形态自行判定。

| 术语或表达             | 含义与使用依据                                       | 描述重点与边界                                                         |
| ---------------------- | ---------------------------------------------------- | ---------------------------------------------------------------------- |
| 粘连                   | 原文明示粘连，或说明应分开的元素连接、原有间隙被填没 | 保留对象是条纹、模块还是点；正常相邻同色模块连续不算使用依据           |
| 间隙缩小、间隙消失     | 原文明确描述间隙变化                                 | 缩小不等于消失；不能把“一团黑”自动转换成间隙消失                       |
| 断裂、断线             | 原文说明本应连续的条纹或结构中断，或明示断裂         | 保留中断位置；正常点阵间隔不能据此写成断裂                             |
| 空洞、缺口、缺点       | 原文明示实体码纹内部的异常空白或缺失                 | “黑条里有白洞”可保留为空洞；不能把二维正常浅色模块当成缺点             |
| 多余点、杂点、间隙填充 | 原文确认不属于码纹的点或明确说明间隙被填充           | 无法确认多余时只保留“斑点”等形态；不推断编码比特错误                   |
| 边缘毛刺、边缘不规则   | 原文描述码纹边缘的突出或不规则                       | 与像素锯齿、模糊分开；不因毛刺确定打印工艺原因                         |
| 条宽或模块尺寸异常     | 原文明示相对于应有结构的异常增宽、变窄或不均         | 不以一维条码天然宽窄差异、二维同色模块组合大小判异常                   |
| 墨迹扩散、渗墨、缺墨   | 人工明确指出印刷现象或原因                           | 可以与粘连、空洞并存，但不由后者反推；“印刷差”也不能展开成这些具体项目 |

**正例：**“右码下面几个模块粘住了，白缝都没了。”→“右侧码区底部部分模块粘连，局部白色间隙消失。”

**反例：**“下面有一大块黑色。”不能直接改成“底部模块严重粘连、墨迹扩散”。

### 3.8 定位与结构性图案受损

这一角度说明受影响的是哪类结构，可与模糊、遮挡、缺损等现象组合。固定图案损伤在条码质量分析中单独受到关注，但不能据此直接断言某处问题必然导致定位或解码失败。[GS1 固定图案损伤说明](https://ref.gs1.org/guidelines/2d-in-retail/)

| 术语或表达                          | 含义与使用依据                       | 描述重点与边界                                             |
| ----------------------------------- | ------------------------------------ | ---------------------------------------------------------- |
| 定位图案受损                        | 人工明确识别定位图案及其问题         | 有具体模糊、遮挡、缺损表现时保留，不只写泛称“受损”         |
| QR 定位图案、校正图案、定时图案异常 | 原文已明确码型及结构名称或无歧义指代 | 不能把所有方块都叫定位图案，也不能自行把位置改为标准方向   |
| Data Matrix 的 L 形边、交替边异常   | 原文明确该码型结构或直接描述这些边   | 保留断裂、缺点、模糊等表现；不把码内部普通边缘当成外部结构 |
| 一维码起始、终止或其他固定结构异常  | 原文已给出该结构身份                 | 不能仅凭左右边缘位置推断起止结构，尤其在码方向未知时       |
| 角部或边缘图案异常                  | 原文只说明位置和形态，未确定结构名称 | 保留普通描述，不为专业化而补码型或结构名称                 |

**正例：**“QR 左上定位框被遮了一半。”→“QR 码左上定位图案一半被遮挡。”保留原文比例，不再估算整个码的遮挡比例；原文若写“大约一半”，则保留“大约”。

**反例：**“左上角的小方块模糊。”不能自动写成“QR 定位图案损坏，无法定位”。

### 3.9 静区与边界干扰

| 术语或表达               | 含义与使用依据                           | 描述重点与边界                                               |
| ------------------------ | ---------------------------------------- | ------------------------------------------------------------ |
| 静区不足、静区缺失       | 人工明确判断静区有问题                   | 保留方向和程度；没有测量及码型依据时不追加合规结论或数值要求 |
| 静区受侵入               | 原文明确文字、边框、图案等进入静区       | 说清侵入对象和方位；“附近有字”不自动等于侵入静区             |
| 外部图案贴近码区         | 原文只说明紧邻或靠近                     | 保留相对关系，不强制升级为静区不足                           |
| 码纹与外部内容相接       | 原文明确说明连接或边界混合               | 保留相接位置和外部对象；不同于码区内部模块粘连               |
| 周边不可见、静区无法判断 | 原文表明裁剪紧、边界未显示或明确无法判断 | 保留观察限制，不能默认为静区正常或不足                       |

**正例：**“右码左边的文字已经进入静区。”→“右侧码区左侧静区被文字侵入。”

**反例：**“裁剪图紧贴码边，没看到留白。”不能直接改成“原码没有静区”。

### 3.10 噪声、纹理与成像伪影

低对比度与纹理干扰可以分别存在；背景复杂也不自动意味着码区内有噪声。Dynamsoft 的预处理说明分别讨论对比度、噪声、纹理及不同区域的照明情况，支持在注解中保留这些区别。[Dynamsoft 图像预处理说明](https://github.com/dynamsoft-docs/barcode-reader-docs/blob/main/programming/features/preprocess-images.md)

| 术语或表达             | 含义与使用依据                       | 描述重点与边界                                               |
| ---------------------- | ------------------------------------ | ------------------------------------------------------------ |
| 噪声、颗粒             | 人工明确称为噪声，或仅描述颗粒状表现 | 仅有颗粒表现时可以保留“颗粒”，不推断传感器、感光度或噪声类型 |
| 斑点、杂点             | 原文描述点状干扰                     | 不自动等于脏污、缺墨或编码错误；“多余”需有原文依据           |
| 底纹、纹理干扰         | 原文说明底纹或纹理影响码区           | 仅背景有纹理时不补“干扰”；保留纹理位置与码纹关系             |
| 透印                   | 人工明确指出另一面的内容透出         | 不由背景杂纹单独推断透印；保留实际进入码区的范围             |
| 摩尔纹、波纹干扰       | 人工明确摩尔纹，或只描述波纹         | 仅描述波纹时保留波纹，不推断拍屏或扫描设备                   |
| 压缩伪影、块状伪影     | 原文明确压缩来源，或仅描述方块状表现 | 已知压缩才写压缩原因；局部方块也可能是正常码元               |
| 锯齿、边缘光晕、伪边缘 | 原文明确相应形态                     | 不自动归因于缩放、锐化或某处理算法                           |

**正例：**“码区底纹里有波纹，没法确定是不是摩尔纹。”→“码区底纹存在波纹，无法确定是否为摩尔纹。”

**反例：**不能改成“拍摄屏幕产生严重摩尔纹”。

## 4 容易混淆的概念与表达处理

### 4.1 异常名称与可见表现

| 容易混用的概念             | 草案采用的区分                                                                                     |
| -------------------------- | -------------------------------------------------------------------------------------------------- |
| 模糊与细节不足             | 模糊描述边缘清晰度；细节不足描述可用细节。只有原文给出像素或缩放信息，才进一步说明采样或缩放问题。 |
| 模糊与粘连                 | “看上去分不开”未必证明实际码纹连接。原文说模糊就保留模糊，原文说粘连就保留粘连，不能相互替换。     |
| 低对比度与过暗             | 一项描述码纹和底色之间的差异，一项描述整体或局部亮度。仅有其中一项不补另一项。                     |
| 发白与反光、过曝、磨损     | 发白是表现，后三者包含不同机制或损伤判断。原因不明时保留发白。                                     |
| 阴影与遮挡                 | 阴影改变亮度，实体遮挡使部分码纹不可见。按照原文命名和关系保留。                                   |
| 裁剪不全与原码残缺         | 裁剪不全说明所见范围，原码残缺说明实体或原图中已确认的缺失。不能从局部图视野直接推断原码。         |
| 旋转与变形                 | 旋转可以不改变内部几何结构；“歪”不足以选定透视、拉伸等原因。                                       |
| 静区不足与码旁有内容       | 靠近是位置关系，进入或占用静区才是明确干扰判断；不自行估算合规性。                                 |
| 模块粘连与正常同色模块相邻 | 粘连需原文明确其异常性质；正常连续黑白区域不能由形状孤立判断。                                     |
| 人眼不可辨与解码失败       | “看不清”描述可见性；“程序读不出”描述实际或人工报告的读取结果。二者不自动互推。                     |

### 4.2 中性特征与异常

旋转、反色、彩色码、点阵成码、曲面载体、金属载体、大图小码、多码密集布局可以是解码相关条件，但自身不自动表示缺陷。

人工明确提供且与解码背景相关时可以保留。保留这些特征不等于认定异常，也不因此补写影响或失败结论。例如“白码黑底，清晰”应保留为“白码黑底，码区清晰”，不能改成“反色异常”。这也不代表认证其符合任何特定标准。

### 4.3 同义表达与过度归一化

| 原文表达                             | 可采用的规范表达                         | 不能自动转换为                 |
| ------------------------------------ | ---------------------------------------- | ------------------------------ |
| 有点糊、稍微模糊，且上下文明示清晰度 | 轻微模糊                                 | 轻微失焦、运动模糊             |
| 黑白差别小                           | 黑白对比度低                             | 曝光不足                       |
| 有双边、同一轮廓错开重复             | 重影，必要时保留重复轮廓描述             | 相机抖动                       |
| 印得糊，其他细节未给出               | 印刷模糊                                 | 模块粘连、缺墨、渗墨的组合     |
| 污损                                 | 污损                                     | 油污、磨损或撕裂中的任一种     |
| 码太小                               | 码区尺寸小                               | 大图小码、像素不足中的特定一种 |
| 看不清                               | 难以辨认                                 | 解码失败、低分辨率             |
| 边上没有留白                         | 边缘无留白，按上下文保留是哪一侧和哪张图 | 已违反某码型静区标准           |

支持不同语言和混合语言的等义规范化，如 low contrast 可写为“低对比度”。保留必要码型、目标编号及原有数值单位，不把含义有歧义的技术词强制映射成更窄的中文异常名称。

## 5 严重程度与具体影响

### 5.1 当前采用的程度规则

优先保留并统一人工已经给出的程度，常用词为“轻微、中度、严重”。不能根据出现了某类异常就默认赋予程度，也不能把主观程度当成质量检测等级。

| 原文                           | 处理方式                           | 理由                                     |
| ------------------------------ | ---------------------------------- | ---------------------------------------- |
| 有点、稍微、轻度模糊           | 可写“轻微模糊”                     | 原文明确表达较低程度                     |
| 中度反光                       | 保留“中度反光”                     | 原文已经给出程度                         |
| 严重、非常严重的遮挡           | 保留“严重遮挡”或原有强度           | 原文明确给出严重程度                     |
| 明显模糊                       | 保留“明显模糊”                     | “容易察觉”不等于“严重”                   |
| 比较模糊、对比度很低           | 保留“较模糊”“对比度很低”等原有量感 | 缺少稳定依据时不硬映射为中度或严重       |
| 大面积反光                     | 保留“大面积反光”                   | 面积属于范围，不是强度                   |
| 只有很小一块，但完全看不见码纹 | 保留范围小及该处码纹不可辨         | 局部不可辨不自动形成全码严重程度         |
| 疑似有轻微拖影                 | 保留“疑似存在轻微拖影”             | 确定性与程度同时存在，不能合并成一个含义 |

### 5.2 用具体表现保留信息

当原文提供具体影响时，优先把它写清楚，而不是压缩成一个等级词。

| 问题类型   | 可保留的具体表现示例                             | 不能追加的结论                     |
| ---------- | ------------------------------------------------ | ---------------------------------- |
| 模糊       | 边缘稍软但条空可分；相邻条空难分；局部码纹不可辨 | 失焦原因、读取必然失败             |
| 低对比度   | 黑白差异小；局部明暗难分；一侧较另一侧淡         | 调制度数值或等级                   |
| 反光或亮斑 | 覆盖部分模块；覆盖处条纹不可辨；周围仍清晰       | 被覆盖部分真实损坏                 |
| 遮挡或缺损 | 覆盖何处、哪些结构、原文明示的比例               | 自动补出整个码的损坏比例或纠错余量 |
| 几何变形   | 条纹弯折；局部模块被压扁；不同部位比例变化       | 自动判定某项标准不合格             |
| 粘连或断裂 | 间隙缩小或消失；局部条纹中断                     | 墨水、打印机或处理算法原因         |

本文不设跨异常通用的三级视觉阈值，也不凭示例建立百分比阈值。当前模型职责是规范已有程度；未来若另行定义视觉评定，需要真实样本和独立判据，不在本次草案中暗含启用。

## 6 多码归属、否定与不确定性

### 6.1 多码与问题位置

- 沿用原文目标标识，例如“左侧码”“右上角码”“码 2”；不自行新编编号或补码型。
- “右侧码区”定位目标，“码区右侧”定位问题，不能互换。
- 同一码的多个问题可合并，但每个问题的范围、程度和不确定性必须对应正确。
- “一个码模糊”保留为“其中一个码区模糊”，不确定为左码或右码。
- “两个码都有反光，只有左码模糊”应明确共同问题和独有问题。
- 不把“整图偏暗”机械展开成每个码都低对比度，也不把一处反光提升为全图异常。
- 原文所指若是裁剪图、放大图或处理后图，应保留该观察对象，避免将处理后的异常归到原图。

**示例：**“左边码有点糊，右边码下半边反光很严重。”→“左侧码区轻微模糊；右侧码区下半部存在严重反光。”不能将两种程度和位置交叉套用。

### 6.2 否定、比较及范围词

“无反光”只否定反光，“边缘清晰”只描述边缘清晰，“可解码”只说明已有读取结论。任何一项都不自动代表整个码区无异常。

| 原文                     | 建议表达                         |
| ------------------------ | -------------------------------- |
| 没有反光，但好像有拖影   | 未见反光，疑似存在拖影。         |
| 左码比右码更模糊         | 左侧码区较右侧码区更模糊。       |
| 只有左码模糊             | 仅左侧码区模糊。                 |
| 大部分清楚，右下角看不清 | 码区大部分清晰，右下角难以辨认。 |
| 不算严重，但也不清楚     | 码区不清晰，程度不算严重。       |

比较关系不能被替换成“左码严重、右码轻微”等未经提供的绝对等级。“仅”“都”“部分”“分别”不能在压缩时丢失。

### 6.3 不确定性与相互冲突的描述

不确定性要落到具体问题上。“模糊确定，反光疑似”不能统一成两个都疑似，也不能统一成两个都确定。“无法判断”与“未检查”也应分别保留，不能都改为“未见异常”。

对于同一目标、同一范围内的矛盾信息，先反馈冲突并提供确认或修正路径，不自行选择一项，不用最后出现的句子覆盖前文。用户无法确认或选择保留未决内容时，能够明确表达冲突的可保留“原描述对……是否存在的表述不一致”；无法理解描述本身时按未完成处理。明确的自我纠正，例如“刚才说反光不对，实际是白色污渍”，可按修正后的有效描述整理，但修正后仍须重新识别歧义和可细化信息。

该冲突处理已写入更新后的规则；相关样例仍需用于核对实际模型在多轮交互中的表现。

## 7 原因、解码结果与观察边界

人工明确给出的原因关系可以保留，但模型不作独立确认。例如“膜的褶皱遮住了条纹”可以保留这种关系；仅有“有膜、有褶皱、有模糊”则不自动合成为“褶皱导致模糊”。疑似原因必须继续带“疑似”或“可能”。

人工明确给出的解码结果、读取条件或尝试范围可以保留。例如“本次用当前参数没读出”不应扩大成“无法解码”；“右码读出来了”也不应变成“右码无异常”。人工只说“看不清”时不补实际读取结果。

图片注解不是条码质量验证报告。GS1 资料中的质量等级依赖测量及验证条件，本文的描述不替代测量，也不从遮挡面积估算纠错能力。[GS1 质量与验证说明](https://ref.gs1.org/guidelines/2d-in-retail/)

对于“未提及异常则按正常处理”的项目约定，当前文本规范化仅沿用其既定范围，不据此生成正常清单。未检查、无法判断、范围外信息不能当作正常；新增这十个分析角度也不表示旧描述已经逐项覆盖。

### 8.2 多轮检查与反馈样例

| 轮次或情形         | 本次收到的信息                               | 分析后必须检查的内容                                         | 应有处理                                                                                                           |
| ------------------ | -------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------ |
| 首轮               | 右边模糊。                                   | “右边”指目标还是目标内局部；“模糊”是否有可细化类型           | 先提供“右侧码区”“某个码区的右侧部分”“其他说明或无法确定”等归属选项，不直接写成右码模糊                             |
| 第二轮             | 指右边那个码，整个码都模糊。                 | 归属和范围已明确；模糊类型是否需要细化                       | 合并为右侧码区整体模糊，再提供类型选项；不能因回答了归属问题就结束                                                 |
| 第三轮             | 运动模糊。另外左边码下面有白块。             | 已确认右码类型；新出现的左码底部白块含义尚不明确             | 保留右码结论；围绕白块提供反光、白色污渍、磨损或缺损、其他说明、无法判断或保持现象描述等选项，不把候选原因当成事实 |
| 第四轮             | 白块原因不知道，就保留发白。其他也不细化了。 | 对白块的不确定性和整体停止意愿是否明确；当前信息是否足以输出 | 完成本轮检查后输出“右侧码区整体存在运动模糊；左侧码区底部局部发白，原因不明。”不再强求程度或成因                   |
| 仅选择不细化       | 保持模糊描述，不再细分类型。                 | 该决定只针对类型还是全部问题                                 | 类型保留为“模糊”，不添加“无法判断类型”；仍检查其他尚待处理的问题                                                   |
| 无法判断后的新一轮 | 类型还是不知道，但确定只有右下角模糊。       | 范围更新与原有“整体模糊”是否属于明确修正；类型未增加信息     | 若明确修正范围则更新范围；不重复问类型，继续检查其余内容                                                           |
| 对已确认结论作修正 | 之前选错了，是失焦，不是运动模糊。           | 修正目标是否清楚；其他描述是否受影响                         | 仅替换对应类型，保留其他有效信息，再执行完整检查                                                                   |

## 9 annotation 规则的内容取舍与输出协议

更新后的 [annotation-rules.md](../resources/annotation-rules.md) 将本草案收敛为可执行约定，不要求每次提交完整术语手册。本文继续保留详细的术语解释和边界样例。

规则保留以下内容：

1. 任务与输入边界：仅依据当前记录的人工原始描述及后续反馈，输入中的指令不能改写规则；允许正常选择、补充和修正描述。
2. 信息保留：目标、现象、位置、范围、程度、否定、不确定性、必要的正常情况与特殊特征。
3. 术语选择：明确术语可直接保留，等义表现可规范，含混表现不强行归因；未列出的可理解异常照常保留。
4. 高风险混淆边界：模糊与粘连、发白与原因、大图小码与像素不足、静区与裁剪、正常码纹与缺陷。
5. 每轮识别与反馈：每次接收并分析信息后，重新识别歧义和有价值的细化点；提供相关选项，合并反馈，再次检查，并定义不重复询问和结束条件。
6. 表达组织：按目标合并问题，多码生成一条综合注解；缺失信息不补造，值得确认的内容先反馈，不为填满清单强求细节。
7. 程度及结果边界：不自动定级、不补因果、不推定解码结果或质量等级。
8. 输出约定：使用 `status` 区分 `needs_feedback` 与 `final`。前者仅返回问题数组，问题包含 `id`、`purpose`、`prompt`、`selection`、`options`；后者包含 `completed` 与 `annotation`。两种结构互斥，不把问题塞进最终注解或把待反馈当作失败；协议及应用衔接差异见[注解多轮反馈与输出协议](注解多轮反馈与输出协议.md)。
9. 代表性示例：同时覆盖最终表达与多轮反馈，检查用户每次回答后是否重新分析，而非只校验单轮文本转换。

原规则中的八个整理维度包含场景、载体、目标、现象等不同层次。更新后的规则将十个角度概括为异常内容范围，同时将目标、位置、程度等保留为贯穿所有异常的表达要求，未将十个角度改为必填项。

## 10 草案复核要点

将原始描述、每轮反馈和最终注解逐项对照，重点检查：

- 是否在每次接收并分析信息后都重新识别歧义和可细化内容，包括选择、修正、无法判断和结束细化。
- 是否区分消除歧义与补充细节；是否因描述已能成句就遗漏有价值的细化机会。
- 是否针对明确目标提供易懂选项，支持并存情况、自由补充、无法判断和不再细化。
- 是否保留已确认信息，是否误把模型候选项、未回复或默认选择当作用户确认。
- 是否对已回答或已关闭的问题重复追问；新增信息引入新问题时是否继续检查。
- 是否满足结束条件后才给出最终结果，待反馈是否与失败、无异常和已完成分开。
- 原文已有的异常是否遗漏，相关正常、否定或不确定性是否被删除。
- 是否把某个码、某个局部的问题扩大到其他目标或全图。
- 是否把现象转成未经提供的原因、具体异常类型或质量结论。
- 是否把正常结构、特殊成像条件直接命名为缺陷。
- 是否把范围大小、明显程度、相对比较机械转换成三级严重程度。
- 是否保留人工报告的解码条件和范围，而没有扩展成普遍结论。
- 是否把未检查、无法判断、信息矛盾误写成无异常。
- 最终结果是否遵守约定的输出格式，是否出现空输入被当作完成、局部正常被当作全图正常的情况。

本草案提供术语使用与信息保留标准。所有示例均为设计样例，可用这些样例和真实人工描述核对更新后的规则；文档与规则更新不代表已经完成模型效果验证或应用侧多轮交互接入。
