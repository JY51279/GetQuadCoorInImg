# 解码背景下的码区注解分析角度

记录日期：2026-10-23

## 目的与范围

注解用于准确表明一张图片中，各个码区存在什么问题、问题发生在哪里，以及码区或码元具体受到怎样的影响。

在解码背景下，观察的核心是：哪些可见现象妨碍了码区被找到、码结构被辨认，以及条、空或模块被正确区分。注解应提供比“图片质量差”“条码不清楚”更具体的信息。

本文单独记录注解规则设计所需的分析角度与判断原则，不涉及筛选、组集或程序实现。以下角度用于组织观察与描述，不要求每条注解填满所有项目。当前人工文本规范化整理原始描述及后续人工反馈，不据此补写未经提供的视觉事实。

## 十个分析角度

这些角度可以同时出现，不必把一个码区强行归入某一种异常。

| 分析角度               | 重点观察的异常情况                                                         | 注解应尽量说明的细节                                                                                         |
| ---------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 尺寸与有效细节         | 码区像素尺寸小，细条或模块难以分辨；缩放后细节丢失                         | 区分“码区占整图比例小”和“码元本身像素不足”。大图小码可能增加定位难度，但不一定缺少码元细节。                 |
| 清晰度与边缘可分辨性   | 模糊、拖影、重影；条空边界或模块边界混在一起                               | 是整个码区还是局部模糊；有无明显拖尾方向；相邻条空是否已难以分开。无法确认原因时只写“模糊”。                 |
| 明暗对比与局部可分辨性 | 码元与底色接近；局部变淡；同一码区内对比度不均                             | 区分整体低对比度与局部对比度下降，指出哪一部分条空或模块难以区分。                                           |
| 光照、反光与曝光表现   | 高光、反光带、阴影、局部过亮或过暗、亮度渐变                               | 光照异常是否进入码区，是否使码纹变淡、消失或难以辨认。背景存在反光不代表码区受到影响。                       |
| 几何形态与变形         | 透视压缩、非均匀拉伸、弯曲、折皱、局部扭曲                                 | 是整体形状变化还是局部变形；哪一侧被压缩；条纹是否弯折、模块排列是否失去规则性。                             |
| 完整性与可见范围       | 码区被画面边缘截断，被物体、标签或其他内容遮挡；局部撕裂、磨损、缺失       | 区分“被挡住”“实物损坏”和“图像未拍全”；指出缺失或不可见的位置，不推测被遮部分的实际状态。                     |
| 条、空与模块的形态缺陷 | 条纹断裂、黑条内部空洞、空白间隙被填充、模块粘连、边缘毛刺、局部缺点或多点 | 说明是黑色部分变宽、白色间隙缩小，还是局部断开、缺失；不能都概括为“污损”。                                   |
| 定位与结构性图案受损   | 用于识别码位置、方向和网格的图案模糊、断裂、遮挡或变形                     | 结合码型指出受影响结构，例如 QR 的定位图案、Data Matrix 的 L 形边及交替边；与普通数据区域受损区分。          |
| 静区与边界干扰         | 码周围空白不足，文字、边框、邻近图案进入静区，码纹与外部内容相接           | 指出哪一侧受干扰，以及干扰来自什么可见内容；需要看到码区周边才能判断，不能仅凭过紧的裁剪图认定原码静区不足。 |
| 噪声、纹理与成像伪影   | 颗粒、斑点、底纹、透印、摩尔纹、压缩块、锯齿或伪边缘                       | 描述干扰是否覆盖码区，是否产生类似码元的图案，或者破坏真实边缘；原因不明确时保留可见表现。                   |

这些角度与实际解码关注的问题相符：GS1 的质量资料区分整体对比、局部明暗变化及固定图案损伤；Dynamsoft 的技术资料也单独讨论小模块、低对比度及纹理噪声等读取困难。本文将这些关注点组织为注解观察角度，不将其直接作为条码质量等级的判据。参考：[GS1 质量说明](https://ref.gs1.org/guidelines/2d-in-retail/)、[Dynamsoft 小模块读取说明](https://www.dynamsoft.com/barcode-reader/docs/core/programming/features/read-barcodes-with-small-module-size.html)、[Dynamsoft 图像预处理说明](https://github.com/dynamsoft-docs/barcode-reader-docs/blob/main/programming/features/preprocess-images.md)。

## 判断与表达原则

### 可见现象与推测原因分开

“相邻模块粘连、间隙缩小”是可以直接描述的表现；“墨水扩散”“打印机故障”则需要额外依据。看到模糊不一定能确定失焦，看到局部发白也不一定能确定反光。

注解应先把表现描述准确，原因仅在有依据时加入。信息不明确或存在有价值的细化点时，先提供相关选项供用户确认；反馈后仍无依据的内容保留原有粒度或不确定性。人工文本规范化时保留人工已有的原因及其确定程度，不自行增加原因，也不把“疑似”“可能”改成确定事实。

### 异常与特殊成像条件分开

旋转、反色、彩色码、点阵成码、金属载体、多码同图，都不应仅凭其存在就认定有缺陷。它们可以是解码相关特征，但需要继续观察具体问题。

- “金属载体”是上下文；“码区中央反光，部分模块不可辨”才是异常表现。
- “多个码排列密集”是布局特征；“邻近码侵入右侧静区”才说明具体干扰。
- “点阵模块”可以是正常成码方式；不能把正常点间空隙直接描述成断裂。

整体背景、载体及原图位置仅在有助于说明问题或区分目标时纳入，不作为必填描述。

### 保留对象、位置和受影响结构

同样是“局部遮挡”，发生在普通数据区、定位图案或码区边界，提供的信息不同。GS1 对 Data Matrix 的说明也分别检查 L 形定位边、交替边及静区。参考：[GS1 DataMatrix 指南](https://www.gs1.org/standards/gs1-datamatrix-guideline/25)。

分析时围绕以下问题组织信息：

- 哪个码受影响？多码图片中的问题应准确归属，不能从一个码扩展到全部码。
- 问题在码区哪里？条码在原图中的位置与问题在码区内的位置应区分。
- 涉及条空、数据模块、定位结构还是静区？
- 是局部还是整体？
- 已经出现什么可见变化？

例如：

> 左侧码区右上部存在条状高光，覆盖部分模块，该处黑白边界难以分辨；右侧码区底部多个模块粘连，局部白色间隙消失。

这种描述比“左码反光，右码印刷差”更具体，也减少了原因推断。缺少对象、位置或结构信息时，检查是否需要反馈澄清或值得细化，不自行补齐。

### 异常程度、影响范围和解码结果分开

局部问题可以很严重，覆盖范围很大也可能只是轻微变淡。程度应尽量依据该问题的可见表现描述，例如“边缘稍软，但条空仍可分辨”或“相邻条空已混为一片”；没有充分依据时，不必强行定级。人工文本规范化时仅保留和规范原文给出的程度，不自行评定。

同一码区的多个问题应分别描述程度，不能把模糊的程度套到反光或遮挡上。

解码成功与否需要实际结果支持。图片存在异常，并不必然解码失败；图片看起来清晰，也不能据此保证解码成功。注解应明确记录可见异常及其作用对象，并保留无法判断的部分，不通过视觉现象直接推定解码结果或条码质量等级。

## 每次分析后的歧义识别与反馈

每一次接收信息并分析后，都重新识别歧义及可细化信息，包括首次描述，以及用户后续的选项选择、补充、修正、无法判断或不再细化等反馈。

流程为：接收并分析信息 → 合并当前记录的有效信息 → 识别歧义及可细化信息 → 有需要则提供选项并等待反馈；收到反馈后重新进入该流程。没有待继续反馈的问题，或用户明确选择结束细化且信息足以忠实表达时，生成最终注解。

- **消除歧义**用于确认原话具体指什么，例如“右边模糊”指右侧码区还是某个码区的右侧部分。
- **补充细节**用于细化已有的有效描述，例如“模糊”未说明类型时，提供运动模糊、失焦模糊、两者都有、其他说明、无法判断或保持原描述等选项。
- 每轮都检查，但不要求每轮都提问，也不为补满十个角度而追问。先处理归属或词义，再处理依赖它们的细分问题。
- 已确认信息继续保留；候选项仅是待确认内容，未回复不视为确认。已表示无法判断或不再细化的项目，在没有新依据或修正时不重复询问。
- 用户回答一个问题后若新增了另一处异常，仍需检查新内容；用户仅表示结束细化时，也要检查合并后的信息并保留未决内容，不能跳过分析。

详细的选项组织、反馈合并、结束条件及多轮示例见[异常术语与描述判据草案](异常术语与描述判据草案.md)。

## 与当前注解规则的关系

本文提供异常分析的内容框架；[异常术语与描述判据草案](异常术语与描述判据草案.md)细化术语和多轮反馈规则。[人工描述规范化与多轮反馈规则](../resources/annotation-rules.md)已按本方案重写，以 `needs_feedback` 返回待确认问题，以 `final` 返回最终注解。完整字段约定及应用侧尚待接入的差异见[注解多轮反馈与输出协议](注解多轮反馈与输出协议.md)。

主要描述异常，正常项不要求逐项补写；人工明确提供的正常情况、否定和不确定性应保留。未观察、无法判断和范围外信息不能由省略推断为正常。
