# QuadTool

QuadTool 是一个仅在本地使用的标准集四边形坐标标注工具，使用 Electron、Vue 3 和 Vite 构建。目前支持 DBR、DDN、DLR 三类 JSON 数据集。

## 使用背景与设计边界

- 本项目仅由维护者本人在离线环境中使用，不计划对外分发或提供给其他用户。
- 输入内容来自维护者信任的本地 JSON 和图片，不处理来源不明的数据。
- 项目不计划加载网络业务内容、接入在线服务或扩展为多人协作工具。
- 当前开发优先级依次是标注正确性、操作体验、数据一致性和本地维护成本。面向不可信 renderer、外部内容或公开分发场景的完整 Electron 安全加固，不属于当前必要范围。
- 所有界面可见的状态与错误反馈统一使用中文，保留 JSON、Quad、DBR、DDN、DLR 等必要术语；开发日志可以保留底层原始异常，便于排查问题。

后续进行设计或代码审核时，应以上述条件作为默认前提。除非使用范围发生变化，或者发现能在当前可信离线场景中实际触发的问题，否则不需要将 preload API 收口、renderer sandbox、IPC 调用来源限制等发布级安全措施列为优先改造项。

## 主要功能

- 加载并识别 DBR、DDN、DLR 数据集。
- 根据 JSON 文件位置解析相对图片路径，也支持绝对路径。
- 浏览数据集图片、查看已有四边形，并通过点击图片选择坐标点。
- 修改或删除当前高亮项，也可以在当前图片的数据末尾添加新项。
- 默认模式用于观察 Quad，并通过选点更新当前高亮项；按 `Tab` 进入直接编辑模式后，才会显示 Quad 顶点和中心拖动手柄，并开启画布悬停联动选择。
- 在直接编辑模式下，当前高亮四边形的四个顶点可直接拖动；释放时重新计算顶点顺序、保存 JSON，并生成一条独立的 JSON 历史记录。
- 在直接编辑模式下，当前高亮四边形可通过中心橙色手柄整体平移；四点始终使用同一位移，触及图片边界时整体限幅，拖动期间保持当前 Quad 激活，释放后只保存一次并生成一条独立历史记录。
- 使用一个点修改已有四边形时，只替换距离该点最近的原坐标点。
- 可通过按钮或 `F` 开关 Quad 聚焦模式；模式开启时，切换激活 Quad 或切换图片后会自动将目标居中，以目标及周边区域占约 75% 视口为首选比例，并尽量避免整张图片的宽高同时小于视口。完整显示 Quad 优先，四周预留 16px（极小视口自动减少）；当目标接近整图或越出图片边界时，必要时降低比例，甚至低于 0.1×，缩放控件范围同步扩展，切图后恢复。手动调整当前视口不会改变该模式。
- 底部工作状态右侧常驻显示 Tab 直接编辑与 F 自动聚焦状态灯；两个模式可独立开启，激活时分别以橙色和蓝色提示。
- 可通过 `Z` 将鼠标所在像素居中，并切换到适合逐像素调整的局部视图。
- 放大图片后显示像素网格和取色预览；网格直接使用浏览器的最近邻绘制，不在内存中保留整张 RGBA 像素副本。
- 窗口调整大小只触发布局重排，不缩放界面字体；应用页面在当前窗口内使用独立倍率并以 100% 启动，图片画布、Quad 覆盖层和像素预览则统一跟随当前屏幕的设备像素比，以适配 Windows 的高 DPI 显示缩放。
- 支持 JPEG、PNG、GIF、BMP、WebP、SVG、ICO、TIFF 和 SVGZ；BMP、动画、矢量、TIFF/SVGZ 以及超过显示上限的图片会先正确解码并转换为单帧 PNG。
- 图片字节不经过 IPC 或 Base64。主进程将输入限制为 64 MB、4000 万像素，将显示图限制在 800 万像素且单边不超过 4096 像素，并通过受控的 `quad-image:` 地址交给渲染进程；坐标按横纵端点比例映射回原图。
- 转换缓存位于应用数据目录，启动时自动清理，运行期间最多保留 512 MB。
- 使用临时文件和替换操作保存 JSON，减少写入中断导致原文件损坏的风险。
- 保存失败时使用当前标注操作的可逆变更记录回滚；没有产生实际数据变化的更新不会重复写入文件。
- 回滚失败或无法确认数据一致性时，停止编辑并要求重新加载图集；不能仅切换图片后继续编辑。
- 启动时尝试恢复最近选择的图集目标及匹配的图片检查点；所选目标加载失败也会保留该目标。恢复记录读取失败会提示，但不阻止手动打开图集。

所有文件都在本机读取和保存，工具不依赖网络服务。

## 使用流程

1. 点击顶部工具栏的“打开图集”选择 JSON。
2. 工具检查数据结构、解析图片路径、打开第一张可用图片，并自动进入“Quad 标注”页。
3. 在图片上点击以添加坐标点；再次点击已有标点可以删除该点，最多同时选择四个点。
4. 在“Quad 标注”页选择标注项；进入 Tab 直接编辑模式后，可拖动当前 Quad 的顶点直接更新，也可拖动中心橙色手柄整体平移；还可使用“更新”“删除”或“新增”按钮。
5. 成功执行数据操作后，JSON 会自动保存到原文件。

加载 JSON 时会先执行只读校验。缺失字段、数量值和连续编号等无损规范化会自动保存；删除无效图片项、把非法坐标重置为零等有损修复会先列出具体数据路径并请求确认。确认后，工具会先在应用数据目录创建临时备份，再替换原文件；备份保留 7 天，到期后会在应用运行期间或下次启动时自动删除。取消则不会修改文件，也不会加载修复后的数据集。

## 快捷键

| 快捷键         | 操作                           |
| -------------- | ------------------------------ |
| `Ctrl+1`       | 打开“图集与图片”页             |
| `Ctrl+2`       | 打开“Quad 标注”页              |
| `Ctrl+3`       | 打开“视图与交互”页             |
| `Ctrl+4`       | 打开“操作历史”页               |
| `Ctrl+O`       | 打开图集 JSON                  |
| `Ctrl+I`       | 手动匹配图片                   |
| `W` / `↑`      | 上一个 JSON 标注项             |
| `S` / `↓`      | 下一个 JSON 标注项             |
| `A` / `←`      | 上一张图片                     |
| `D` / `→`      | 下一张图片                     |
| `Ctrl+S`       | 修改当前高亮项                 |
| `Ctrl+E`       | 沿用上图同下标 Quad 坐标       |
| `Ctrl+D`       | 删除当前高亮项                 |
| `Ctrl+A`       | 在当前图片的数据末尾添加标注项 |
| `C`            | 清空待提交的 P1–P4 坐标点      |
| `Ctrl+Z`       | 撤回选点                       |
| `Ctrl+Y`       | 重做选点                       |
| `Ctrl+Shift+Z` | 撤销 JSON 操作                 |
| `Ctrl+Shift+Y` | 重做 JSON 操作                 |
| `R`            | 重置图片位置                   |
| `F`            | 开关 Quad 聚焦模式             |
| `Z`            | 居中并放大鼠标所在像素         |
| `Q`            | 切换当前高亮四边形的显示状态   |
| `Ctrl+Q`       | 隐藏全部四边形                 |
| `Ctrl+Shift+Q` | 显示全部四边形                 |
| `Tab`          | 切换默认与直接编辑模式         |
| `F1`           | 打开或关闭快捷键帮助           |
| `1`–`4`        | 删除相应序号的当前标点         |
| `Esc`          | 取消正在进行的 Quad 拖动       |

在输入框中输入内容时，全局快捷键不会触发。

使用 `W` / `↑` 从第一个 Quad 继续向前，或使用 `S` / `↓` 从最后一个 Quad 继续向后时，会进入未激活状态。未激活时再次向前会选择最大下标，再次向后会选择最小下标。

“操作历史”页按图片显示当前会话中已保存的 JSON 操作和保存时间。当前图片的记录可以点击跳转，其他图片的记录只读；一次跨越多条记录的跳转只会保存和刷新一次。每张图片最多保留 30 条，整个图集最多保留 100 条，超限时会淘汰最久未编辑的非当前图片历史。关闭应用或更换图集后，会话历史会被清空。

## 安装和开发

开发工具链限定为 Node.js `>=22.17.1 <23`、npm `>=10.9.2 <11`。已验证基线是 Windows x64 / Node.js `22.17.1` / npm `10.9.2`，`.nvmrc` 记录该 Node 基线；这不是“最新版本”声明。使用其他平台或升级工具链后，需要重新执行干净安装和完整检查。

`package.json` 中的 `engines` 声明版本范围，npm 10.9.2 的 `devEngines` 会在安装和运行脚本前检查开发工具链。首次安装或依赖发生变化时执行：

```powershell
npm ci
```

启动开发模式：

```powershell
npm run dev
```

开发服务器支持渲染端热更新。若安装依赖时遇到 `EPERM` 或文件占用错误，请先关闭正在运行的 QuadTool、Electron 开发进程和相关终端。

## 检查和测试

```powershell
npm test               # 运行单元、组合契约及 Vue 组件测试，不采集覆盖率
npm run test:coverage  # 全量测试、关键模块逐文件覆盖率门槛、生成报告
npm run lint:check     # 检查 ESLint 错误，不修改文件
npm run format:check   # 检查受管理文件的格式，不修改文件
npm run check          # 格式检查、测试及覆盖率门槛、静态检查、生产构建
```

自动修复命令：

```powershell
npm run lint
npm run format
```

`format` 只处理项目源码、配置和文档；构建产物、依赖、覆盖率报告、测试数据以及图片资源已被排除。

覆盖率统计全部 `src/**/*.js` 和 `src/**/*.vue`，包括未导入源码，不隐藏启动入口和薄覆盖的界面模块。`coverage/index.html` 可查看逐行详情，`coverage/coverage-summary.json` 和 `coverage/coverage-final.json` 供机器读取；报告可重新生成，不提交 Git。关键门槛以 `vitest.config.mjs` 为准，按模块逐文件检查，不用平均值掩盖回退。当前基线、门槛策略和未覆盖范围见[阶段 5 质量保障记录](docs/phase-5-quality-assurance.md)。

局部调试使用 `npm test -- tests/WorkflowState.test.js`；覆盖率命令要求全量运行，过滤测试可能因其他关键模块未被执行而触发门槛失败。新增功能和缺陷修复应同时补充最终数据、历史、工作流终态和副作用断言，不能只检查函数调用次数。

测试按职责覆盖数据模式、数据集状态与变更、历史、图片几何、手势、服务、IPC、Vue 组件和跨层异常序列。部分文件测试使用真实临时文件；Electron 原生对话框、IPC 传输和 Canvas 绘制仍有模拟边界，不等于完整桌面验证。[既有人工冒烟清单](docs/manual-smoke-test.md)保留，但本轮按要求不新增、不执行；当前个人离线场景不引入完整 Electron E2E 框架。

## 构建和打包

```powershell
npm run build          # 构建到 out，不生成安装包
npm run start          # 运行已经构建好的版本
npm run build:unpack   # 生成未安装版程序目录
npm run build:win      # 生成 Windows 安装程序
```

Windows 打包结果通常位于 `dist`。项目同时保留了 `build:mac` 和 `build:linux` 命令，但需要对应的构建环境。

## 项目结构

```text
src/
├─ main/
│  ├─ index.js                 Electron 主进程入口
│  ├─ IpcHandlers.js           文件选择、图片读取和保存相关 IPC
│  ├─ FileOperations.js        路径、JSON 读取和原子保存
│  ├─ ImageFileReader.js       图片限幅、转换缓存和安全资源协议
│  └─ WorkspaceSessionStore.js 串行持久化最近目标与图片检查点
├─ preload/
│  └─ index.js                 向渲染端暴露 Electron API
├─ shared/                     IPC 通道、服务结果、文件响应及会话契约
└─ renderer/src/
   ├─ composables/
   │  ├─ useWorkspaceDataset.js 图集加载、启动恢复与目标选择编排
   │  ├─ useWorkspaceImages.js  图片会话、请求重试与失败恢复
   │  ├─ useWorkspaceEditing.js 编辑命令、保存及成功历史编排
   │  ├─ useDatasetLoadTransaction.js 目标绑定、数据准备与提交
   │  ├─ useDatasetSaveTransaction.js 保存互斥、失败回滚与恢复态
   │  ├─ use*Gesture.js        画布、顶点和整框/边手势的捕获与取消
   │  └─ 其他 composable       视口、覆盖层、历史、选点和通知
   ├─ services/               图集准备、图片请求、JSON 保存及会话协议边界
   ├─ components/
   │  ├─ WindowProcess.vue     页面装配、局部视图状态、权限及事件绑定
   │  ├─ ImageView.vue         图片会话呈现、Canvas 绘制和交互绑定
   │  ├─ WorkspaceToolbar.vue 工具栏展示与操作事件
   │  ├─ DatasetInfoPanel.vue  图集/图片信息展示与操作事件
   │  └─ JsonView / HistoryView / Help.vue  内容、历史与帮助展示
   ├─ state/
   │  ├─ DatasetState.js       已提交数据、受控命令、历史应用与回滚记录
   │  ├─ WorkflowState.js      纯工作流转换、操作身份与权限守卫
   │  ├─ ImageSession.js       不可变图片元数据和图集版本归属
   │  ├─ PointerGestureState.js 纯指针手势转换
   │  └─ 其他 state            历史容量/双栈、Quad 选择和独立交互模式
   └─ utils/                   纯数据准备、几何/坐标换算、图片解码与绘制调度
tests/                         单元、组件与跨层契约回归
docs/                          行为契约、分阶段实施及质量保障记录
```

这个项目面向个人本地使用，当前结构以直接、容易定位为原则，不额外引入路由、全局状态框架或服务端组件。
